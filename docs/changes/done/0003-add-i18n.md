# 0003 — Add I18n

> Status: **open** · Type: **feature** · Created: 2026-06-24

## Goal
Frontend needs to support other languages besides English for text field names/dropdown values, formats (N Calories).

## Context
App needs to have a translation mapping file or similar according to best practices for this stack. The mapping will be updated as needed to add languages and translate new text items.
Any not translated items default to English lang.

Get user's language from `Accept-Language` header, default to English if no matching lang.

Add Ukrainian as new supported language.

"Save" button on main page is not easily translated, in other langs the lenght of translated word might be longer, whick makes it harder to focus on button. Replace with either diskette emoji or smth more obvious

## Acceptance criteria
- [x] If Accept-Langauge header contains Ukrainian lang mark(check specification for exact value) "N kcal today", time slot values (Lunch, Breakfast...), List selector values(Recent(same meal), Top overall...), buttons "Add missing" on main page are displayed in Ukrainian.
- [x] If Accept-Langauge header contains Ukrainian lang mark(check specification for exact value) "New food", "(per 100 g)", nutrions field names("Name","Calories"...), buttons "Cancel" and "Save food" on Add missing modal page are displayed in Ukrainian.
- [x] For any other Accept-Language header value all listed in previous acceptance criterias displayed in English.
- [x] "Save" button on main page replaced either by diskette emoji or smth else

## Scope / hints (optional)
- Affected areas: Static text on frontend, format strings
- Out of scope: Text fetched from DB (Food names)

## Notes / decisions
- Language is detected client-side via `navigator.languages` (the same ordered list the browser sends as `Accept-Language`), so no server round-trip is needed. Checking for the `uk` prefix covers both `uk` and `uk-UA`.
- `?lang=uk` URL param overrides detection — handy for testing without changing browser locale settings.
- Translation strings live in `frontend/src/lib/i18n.js` as a plain JS object with `en` and `uk` keys. Any missing key falls back to English. Adding a new language means adding one entry to that object.
- Parameterised strings (e.g. "X is required") are stored as functions `(label) => \`...\`` so they compose naturally with translated label names.
- `Save` button replaced with 💾 (U+1F4BE floppy disk) — language-neutral, avoids width issues with longer translated words.
